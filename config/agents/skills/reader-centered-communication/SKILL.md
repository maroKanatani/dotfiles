# 読み手中心のコミュニケーションを書く

質問、依頼、報告、説明の意図を一目で伝え、読み手が文中を往復せずに回答または行動できる文章にする。

## コアを固める

1. 伝えたいこと、または確認したいことを一文に圧縮する。圧縮できない場合は文章を作り始めない。
2. 質問では、回答によって決まる仕様、判断、次の行動を明確にする。答えが出ても何も変わらない質問は削る。
3. 手元の資料や過去の発言を確認し、答えを既に知っている質問は削る。既知の事実は前提として書き、訂正の機会だけが必要なら「認識違いがあればご指摘ください」と添える。
4. 完成後に文章を一文へ圧縮し直し、最初のコアと一致するか検算する。

## 読む順序を整える

- 質問は確認事項、依頼は求める行動と期限、報告は結果を先頭に置く。説明は要点を先頭に置く。
- 各ブロックを単独で理解できる形にする。「上記」「前述」「別表参照」など、読み手を別の箇所へ移動させる参照を使わない。
- 事実と質問を別々のリストに分けない。回答に必要な事実は、対応する質問のブロックに入れる。
- 略語や凡例は使う箇所の直近で説明する。
- 数量や状態には対象の名詞を付ける。「有効1件」ではなく「有効アカウント1件」と書く。
- 背景は、質問だけでは回答がぶれる場合、または過去の発言との食い違いを扱う場合だけ、質問の後に短く置く。質問だけで通じる場合は背景を削る。

## 答えやすい質問にする

- 一つの質問には一つの命題だけを置く。別の解釈や裏取りを同じ質問へ重ねない。
- はい・いいえ、または選択肢で答えられる形を優先する。
- 自分の仮説や有力な選択肢を質問に添える。白紙の「どうすればよいですか」を投げない。
- 一文へ詰め込まず、短い文に分けて認知負荷を下げる。

## 根拠を対応させる

- 出典と確認時点を、対応する主張の近くに書く。「データで確認した」ではなく、何を、いつ時点の資料で確認したかを書く。
- 画面、データベース、口頭説明など、異なる出典の事実を同じ文へ混ぜない。出典ごとに文を分ける。
- 書き終えたら文ごとに出典と矛盾の有無を確認する。根拠の範囲を越える断定は、確認できた範囲へ狭める。

## 型を使う

質問は、必要な背景だけを確認事項の後へ置く。

```text
確認事項
・〜は、〜という理解でよろしいでしょうか。

背景
・〜で〜を確認したところ、〜だったため。
```

質問ごとに背景が異なる場合は、確認事項と背景を一組にして並べる。全質問に共通する背景だけは、確認事項の一覧の後にまとめる。

報告は、結果、根拠、留保の順に書く。

```text
［結果］〜でした。／〜を確認できました。
［根拠］〜（出典・確認時点）で〜を確認しました。
［留保］ただし、〜は未確認です。
```

依頼は、求める行動と期限を先頭に置く。

```text
［依頼］〜を〜までにお願いします。
［背景］〜のため必要です。（理由が自明なら省く）
［補足］手順・材料は〜です。
```

## 最終確認

- 各ブロックの一文目だけで、何を確認、依頼、報告、説明しているか分かるか。
- 質問の答えによって判断または行動が変わるか。既知の答えを聞き直していないか。
- 質問は一命題で、読み手が回答を始められる形か。
- 必要な事実、出典、確認時点が対応するブロック内にあるか。
- 読み手が別の箇所へ移動せずに理解できるか。
