# 日本語技術文書を書く

技術的な内容を、対象読者が根拠を追いながら理解できる文章にする。
表面的な言い換えより、論証の順序と命題の正確さを優先する。

## 執筆手順

1. 対象読者、文書の目的、読後に理解してほしい結論を定める。
2. 事実、推論、判断を分け、主張を支える根拠を集める。確認していない内容は断定しない。
3. 各節が答える問いを一つに絞り、前提から結論へ一方向に進む構成を作る。
4. 一つの段落に一つの論点を置く。段落の最初で対象を示し、根拠、説明、帰結を続ける。
5. 用語、因果関係、不確実性、参照先を点検し、重複と不要な演出を削る。

## 文章の規範

- 事実と推論を区別する。ログからの推定、将来の可能性、反実仮想に必要な不確実性は残す。
- 因果を述べるときは、結果だけでなく、なぜその結果になるのかを説明する。
- 例が主張の一部しか支えない場合は、主張の範囲を例に合わせて狭める。
- 同じ概念には同じ用語を使う。技術用語は分野で定着した訳語を優先し、独自の言い換えで意味をぼかさない。
- 行為者が重要な文では主語を示す。受動態の連続や「AI」「ツール」のような広すぎる語を避け、対象を具体的に書く。
- 読者が後で使わない固有名、数値、実装詳細は省く。ただし、結論を支える具体は削らない。
- 見出しは、その節の問いまたは対象が分かる句にする。内容のない見出しや、結論を誇張した決め台詞にしない。
- Markdown原稿では原則として一文ごとに改行し、段落間に空行を置く。コード、設定、ログはコードブロックに分ける。
- 空虚な強調、過剰な比喩、劇的な転回、同じ主張の言い換えを削る。特定の語を機械的に禁止せず、その語が情報を増やしているかで判断する。

## 最終確認

- 各段落の役割を一文で説明できるか。
- 主張ごとに根拠があり、その根拠が主張全体を支えているか。
- 定義、分類、用語が文書全体で一致しているか。
- 未確認事項を確認済みの事実として書いていないか。
- 読者が前の段落へ戻らなくても、指示対象と論理関係を追えるか。
- 導入、例、結論で同じ内容を繰り返していないか。
